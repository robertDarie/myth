# Balance migration and population contract

Plan recorded before production balance edits, 2026-11-14. A/B/C are already published. Numeric, calibrated Forsaken, world population and special PvE are separate subsequent checkpoints. This document distinguishes the intended contract from delivered work; until each checkpoint is verified, it is pending.

## Compatibility plan

Persist a numeric profile version and advance the world schema with migration tests. Production uses the new profile; old regression fixtures explicitly select the legacy profile to preserve evidence about old mechanics. New tests must exercise production numbers; legacy regression results alone do not certify the new balance. Client input cannot choose the profile.

Old unit state has real typed counts, T1 health5/4/5 and attack0.75/0.95/0.85. T2 health×1.4 attack×1.35; later tiers health×1.22 attack×1.18. Old tier power is 5/8/12/17/23. New troop power is 1/2/3/4/10, with documented troop attributes and an explicitly provisional damage conversion coefficient; original civilian and commander modifiers remain. Defense must influence combat, rather than being a decorative statistic.

Convert legacy mortal counts exactly ×50 across deployed armies, reserves, wounded, treatment and prepaid training/promotion jobs; mythic counts stay unchanged. Preserve health fractions, resources, cargo, names, commander ownership and immutable historical reports. Existing paid queue duration and cost remain honored; converted jobs carry an explicit migration receipt. Conversion must run once, reject invalid originals before scaling, and never mutate the caller's save object. Existing battle/rally restart interruption rules apply before conversion; safe travel/gather/return orders remain. Store an audit of old counts. Real troop accounting and conservation must be asserted after reload. Do not edit real saved kingdoms during development.

Old aggregate city cap 40/80/140/220/340 (+Hall bonus5) and per-slot division are replaced: operational city storage is a ToM bound of ten million mortal troops; march base maps the five ages to published City Hall levels1/6/11/16/25 (2000/9000/28000/57000/150000), plus primary commander capacity. Missing commander rows interpolate and are explicitly inferred. Commander capacity never adds the secondary commander. Legacy armies above a new march limit remain valid; resizing/new deployments obey limits.

Old batches5/5/10/20/40 become ToM batches100/200/500/1000/2000, not claimed as RoK queue sizes. Costs and training seconds are per real soldier using documented troop rows; speed modifiers stay original. Promotion uses the difference between source and destination costs and times. Hospital treatment batch capacity scales ×50, conserves all admitted wounded and retains existing nonlethal overflow policy; this is not exact RoK hospital behavior. Fort/rally limits must support large real armies and existing Godbreaker difficulty must scale alongside them. Building/research/commander power stays an original formula until verified tables are available, and must be disclosed.

Old AP cap100, interval60000ms and ordinary cost5 become1500,36000ms,50. Preserve the balance fraction (×15) and fractional regeneration progress (×0.6); keep generation entitlements so movement/restart cannot re-charge a paid fight. No chain discount without a verified floor. Existing AP items keep stable IDs; changed effects must be documented. No premium AP purchasing.

## Pending calibrated Forsaken checkpoint

Ordinary identity is Forsaken Lv.1–25; preserve the stable seven original IDs. Use the checked reference data with missing NPC counts explicitly inferred, and explicit mortal composition/tier assumptions. Displayed enemy power remains separate from simulation damage. Per-level engine simulations must measure ordinary, fewer, more, stronger commander, higher/lower tier and technology cases, recording real HP, wounded, AP, XP and loot. No invented measurement.

Victory receipts use stable entity ID and generation, once-only rewards and durable revision changes. Each participating commander receives base100×level XP; loot pool probabilities remain explicitly ToM policy where unknown. First-clear progression is distinct from repeat loot.

## Pending population checkpoint

Bounded regional quotas and global cap; stagger region evaluation every few seconds with a fixed candidate budget. Respect map bounds, gate-free paths within each region, city/structure clearance, local separation and fog. Avoid observed pop-in where practical. Reuse stable dead slots with generation increment and a newly sampled anchor after delay. Persist patrol target, anchor, pause clock, generation and position. Smooth movement stays within a bounded home radius; combat pauses patrol. Disengagement returns home, never pursues indefinitely. Validate path segments as well as endpoints. Search accepts unlocked levels, respects visibility and rate-limits any low-level near-city creation. Hidden moving targets must never leak current coordinates through attacker navigation or snapshot destinations.

## Balance implementation

Schema27 / numeric profile1 is the production default. Profile0 is an explicitly isolated regression fixture and is not exposed through player commands. The code implements the compatibility plan above. New cities receive900 real T1 soldiers, food/wood10000 and gold1000 so one reference-priced training order is affordable. Existing stockpiles are unchanged. Node capacity scales100× (migration preserves remaining stock); new nodes start full, gathering speed scales10× and passive stock ceilings1000×. These are ToM economy adaptations, not claimed as RoK production formulas. Per-soldier load uses the reference attribute. AP tonic remains20 AP with its stable ID and no overflow consumption.

Commander Common/Rare map to reference Advanced/Elite. XP rows2–59 are interpreted as incremental requirements to reach the row level. Missing final-level cost repeats the preceding cost provisionally; Advanced30 corrects an obvious malformed number by inference, Advanced49/50 retain the printed anomalies, and missing Advanced51+ use the usual0.6 ratio provisionally. XP is cumulative and migration preserves level, fractional progress and experience banked above the current star cap. Original stars, skills, mentors and talent rules remain. Commander power now uses the actual level, while its coefficients and building/research power remain original.

The aggregate damage coefficient is0.05 times per-soldier reference attack, multiplied by existing commander/civilization/research effects; target defense applies120/defense. Health sums real soldier health before existing modifiers. This is a transparent ToM approximation, not an exact internal RoK equation. Wounds retain the existing25% severe-wound transfer on defeat (now including ordinary PvE), with no lethal overflow. Godbreaker guard/wall health scales1000×, retaliation200×, garrison units50×, ordinary-resource payouts100× and XP4×; Oracle Sigils stay unchanged. Alliance fortification health/repair scales1000×. These preserve the old encounter identities while special-content calibration remains pending. Rally load1.5m and garrison load1m are explicit ToM limits.

Ordinary camps temporarily use level-specific reference health/attack/defense and base100×level XP per participating commander, including a secondary. Their expanded identities/rewards/unlocks and all25 measured calibration cases belong to the next checkpoint. Discounts remain disabled. Old immutable reports retain old numbers and original rewards.

Original mythic escorts keep their actual counts and recruitment caps. Their health35000, attack2400 and troop power225 are explicit ToM adaptations preserving a useful escort at the new starting scale, not reference troop rows. Legacy troop stacks over the former100000-per-type bound are rejected before migration.
