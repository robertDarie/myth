# Interface 0.6: a map-first strategy game

This is an original Thrones of Myth interface informed by familiar kingdom-builder
interaction patterns. It does not include copied game assets or a finished art
replacement for the current world and characters.

## Layout

- **Top:** player identity and age, six resource counters, connection status,
  interface settings. Hovering resource counters shows their exact values;
  selecting one opens its relevant economy or Temple screen.
- **Left:** collapsible chapter progress and active construction/research jobs.
  Claim completed chapter rewards directly or open the Chronicle.
- **Right:** five march positions, with portraits, health/rage bars and locked
  age states. Select an existing march or open deployment for an available slot.
- **Bottom:** City, Commanders, Alliance, Temple and Chronicle navigation, plus
  a compact kingdom minimap.
- **Selection:** camps, resources, sacred sites, armies and cities get a context
  card with relevant actions. The full-screen management panel is no longer
  permanently attached to the map.

The world keeps running while management windows are open. A visible selected
march and server-owned commands remain the source of truth.

## Management screens

**City:** a four-column institution grid (three on narrower views), selected
building details, costs, missing requirements, construction action and both crew
jobs. Training, research, Temple, Forge and Market have direct shortcuts.

**Athenaeum:** a research graph connected by actual prerequisite IDs, selected
technology effects, rank, cost, research time, unmet conditions and active job.

**Commanders:** searchable roster, rarity filters, owned-only option, large
commander illustration, assignment state, individual XP/stars/skills and
ascension. Unrecruited commanders can be inspected before recruiting. Commander
assignment still requires the selected march idle at home.

**Temple:** a large summon stage, brief result reveal, single/ten invocation,
explicit sigil costs, daily offering and exchange, visible base/conditional odds,
persistent guarantees and recent results. There are no hidden auto-purchases.

**Other activities:** training, march composition, alliance help, forging, market
exchanges and Chronicle use larger themed panes with scrollable detail areas.
Only implemented gameplay actions are presented; there are no fake PvP or shop
buttons.

## Interaction and accessibility

- Right-click remains the quick map order; left-click inspects/selects.
- Number keys 1–5 select and focus marches. C opens City, K Commanders, L Alliance.
- H focuses home, Space focuses the selected march, R recalls it.
- Escape closes a management window, cancels beacon placement, or clears the
  current selection, in that order. Navigation cancels beacon placement cleanly.
- Clicking interface controls is blocked from issuing orders through to the map.
  Pointer hit testing uses the same scaled coordinate system as the layout.
- Keyboard camera controls are suspended in management windows. Text entry in
  commander search cannot trigger map commands.
- Interface size ranges from 85–115%, with automatic fit to the window. World
  labels can be toggled. Preferences are saved locally.
- Resource labels are hidden at distant zoom, reducing map clutter. Selected
  targets retain labels; named sites and marches remain visible where uncovered.
- Command feedback uses player-facing messages rather than internal API names.
  Connection/save problems have persistent messages when they occur.

## Art and implementation

The palette is deep navy, bronze/gold, cream text and teal progress indicators.
Panels have rounded, beveled edges, hover/pressed states and a consistent type
hierarchy. Resource and institution symbols and commander medallions are original
procedural graphics, generated by the client without extra downloads. They are
not final bespoke character paintings or production city art.

The existing MonoBehaviour is split across partial class files: transport/core
commands, interface layout, and management screens. `MythInterfaceTheme` owns
styles and generated textures and disposes them with the client. Input protection
is also checked by the camera independently of script Update order.

No backend gameplay progression changes are required. Version 0.6 still uses
protocol 5 / save schema 3; march destinations are additive snapshot fields used
for the selected march route. Rebuilding an existing prototype scene is optional.

## Windows review

Pull main and build a fresh Windows package. Check at 1280×720, 1366×768 and
1920×1080, and try both interface-size extremes:

1. Join/resume, then verify every resource counter and march assignment.
2. Open and close each menu via navigation and Escape. Orders must not fire
   through panels when selecting, scrolling or typing in search.
3. Build an institution and run both crews; HUD progress must match the City pane.
4. Select research nodes, inspect prerequisites and start a real research job.
5. Inspect an owned/unowned commander and test one eligible development action.
6. Invoke a Temple echo; verify the displayed result, wallet, history and odds.
7. Select a camp/resource/site on the map and issue an order via the context card.
8. Place a beacon from Alliance; the modal should close and placement should
   work on the map. Escape should cancel that placement.
9. Select/focus different marches, use the minimap and adjust label visibility.
10. Close/reopen the game; confirm existing city progress and UI preferences.

Cloud checks cover C# syntax, internal method bindings, packaging dependencies
and server regressions. A layout preview was reviewed, but no Unity compilation
or native Windows rendering was performed in the cloud.
